### 2.1 · Is Vault purchasable as its own subscription? · **SCHEMA YES · UI NO**

Schema is independent:
`nex-supabase/migrations/257_nex_account_independent_shop_vault_entitlements.sql:211-216`

Backfill (line 336) set `shop_tier='unlimited'` for existing bisnis

standalone subscription.

**However** no UI surfaces purchase of a Vault-only subscription today.
The `/nex-native/store` catalog (`src/app/nex-native/store/page.tsx`)
lists Vault with label *"Included with NEX Shop"* (line 67-100). No

### 2.2 · Is Vault entangled with Shop today? · **YES — SEAL VIOLATION**

**`src/app/nex-native/vault/page.tsx:41-45`** gates Vault access on
`shop_tier` being non-null:

function isShopEntitled(shopTier) {
  // Vault is gated on paid NEX Shop plan ownership.  ← seal violation

to unlock Vault. Line 73-75 — if entitled to Shop AND no vault setup →

at `src/lib/nex-native/vault/vault-service.ts:18-35` correctly checks
`vault_tier` OR 7-day `vault_trial_used_at` — it does NOT read
`shop_tier`. The defect is only in the page gate.

Cancellation service comment (`cancellation.ts:7-8`) correctly states
*"Shop and Vault cancellation are INDEPENDENT"* — the gate contradicts
the comment, the schema, and the 2026-11-25 seal.

### 4.4 · Peer-message identity-domain mismatch · **CONFIRMED**

Current (migration 047, lines 100-102):
```sql
participant_a_id = auth.uid()
OR participant_b_id = auth.uid()
```

`participant_a_id` / `participant_b_id` columns reference `nex_account.id`,
which is **not** the same as `auth.uid()` (which equals
`nex_account.supabase_user_id`). Comparison is between two UUIDs from
different identity domains → almost always FALSE → deny-safe but
broken.

Fix authored in migration 218, lines 128-134:
```sql
participant_a_id IN (SELECT nex_current_account_ids())
OR participant_b_id IN (SELECT nex_current_account_ids())
```

Helper `nex_current_account_ids()` at
`010_nex_rls_recursion_fix.sql:48-55` maps
`auth.uid() → nex_account.id` via `supabase_user_id`.

**218 is NOT APPLIED → identity-domain mismatch is LIVE.** Service-role
bypass is currently the only working path for peer messaging.
